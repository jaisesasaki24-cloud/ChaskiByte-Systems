LÍMITES CRÍTICOS DEL MODELO MONOLÍTICO

¿Por qué el e-commerce de cómputo de alta gama exige arquitectura de microservicios?

💥 1. Colapso en Alta Demanda

Eventos como CyberDays o lanzamientos de CPUs Ryzen/RTX provocan miles de consultas masivas.

  • ✖ La lectura satura la cola de procesamiento del monolito.
  • ✖ El servidor de ventas se congela y no se cobran pedidos.
  • ✖ Pérdida directa de facturación y abandono de clientes.

⛓️ 2. Punto Único de Falla (SPOF)

En un monolito todos los módulos conviven en el mismo ejecutable y JVM.

  • ✖ Si falla la pasarela o el cotizador, se paraliza la tienda.
  • ✖ Un bug en reportes tumba el carrito de compras.
  • ✖ Cero aislamiento de fallos ni tolerancia activa.

📈 3. Escalado Ineficiente

El catálogo se consulta hasta 10 veces más de lo que se concreta en compras.

  • ✖ El monolito obliga a duplicar toda la aplicación completa.
  • ✖ Desperdicio crítico de memoria RAM y núcleos de CPU.
  • ✔ Microservicios: Permite escalar solo el servicio saturado.

CONFIGURACIÓN EXTERNALIZADA DEV VS PROD

El mismo artefacto JAR opera en desarrollo y producción sin recompilar

🛠️ Perfil DEV (orden-ms-dev.yml)

Configuración para desarrollo ágil en máquina de laboratorio:

  • ▪ Base de datos local: localhost:5433/orden_db.
  • ▪ DDL Hibernate: update para iteración rápida sin scripts manuales.
  • ▪ Nivel de Log: DEBUG para diagnóstico detallado en consola.
  • ▪ Actuator: Expone health, info, metrics y prometheus.
  • ▪ Eureka Server: Registro en http://localhost:8761/eureka/.

🚀 Perfil PROD (orden-ms-prod.yml)

Configuración aislada de alta seguridad para producción:

  • ▪ Red interna Docker aislada: pagatu-prod-net.
  • ▪ Credenciales protegidas: Variables ${POSTGRES_USER} y ${POSTGRES_PASSWORD}.
  • ▪ DDL Hibernate: validate para proteger la integridad de datos.
  • ▪ Actuator seguro: Información sensible oculta al exterior.
  • ▪ Resolución de host por nombre de contenedor en Docker.
PILAR 2: MATRIZ DE MAPEO
HABLA: ELICEO PARILLO MOSTAJO

MATRIZ INTEGRAL DE MAPEO MULTICAPA

Mapeo desacoplado en Gateway, Eureka, Hibernate JPA y Códigos HTTP

🗺️ Mapeo Multicapa del Ecosistema ChaskiPC

  • 1. Mapeo Gateway: /api/v1/ordenes/** -> lb://pagatu-orden-ms (Round Robin entre :8082 y :8083).
  • 2. Mapeo Gateway: /api/v1/productos/** -> lb://pagatu-catalogo-ms (Puerto :8081).
  • 3. Mapeo Gateway: /api/v1/pagos/** -> lb://pc-pago-ms | /api/v1/auth/** -> lb://pc-auth-ms.
  • 4. Mapeo Eureka: spring.application.name coincide en mayúsculas; instance-id dinámico evita colisión.
  • 5. Mapeo JPA: @Entity Orden (@Table 'ordenes') y DetalleOrden (@Table 'orden_detalles') con @OneToMany.
  • 6. Mapeo Jackson: @JsonManagedReference y @JsonBackReference evitan bucles cíclicos recursivos en JSON.
  • 7. Mapeo Códigos HTTP: 201 Created (alta), 200 OK (consulta), 400 Bad Request (validación), 404 Not Found.
